# UI Kit и система тем

## Структура слоев

### Контракты

**Путь:** `lib/core/ui_kit/src/theme/`
**Компоненты:** `BaseColors`, `BaseLayout`, `BaseTextStyles`

Интерфейсы дизайн-системы. Виджеты запрашивают семантические значения
(`context.colors.primary`) без привязки к конкретной теме -- не знают, светлая она или темная.

### Реализации

**Путь:** `lib/core/ui_kit/src/theme/[colors, layout, typography]/`
**Компоненты:** `AppLightColors`, `AppDarkColors`, `AppTextStyles`, `AppLayout`

Конкретные значения для каждого контракта. `AppThemeData` маппит их в нативный `ThemeData`
и регистрирует через `ThemeExtension`.

### Управление

**Путь:** `lib/core/ui_kit/src/theme/app_theme_manager.dart`
**Компонент:** `AppThemeManager`

Оркестратор темы:
- Инициализация из локального хранилища
- Отслеживание системной яркости через `platformDispatcher`
- Переключение между `light`, `dark` и `system`

## Ключевые решения

### ThemeExtension вместо глобальных констант

Расширения позволяют прокидывать через контекст любые кастомные параметры.
Пример: для разных тем нужны разные логотипы -- создается `AppAssetsExtension`,
в `AppThemeData` для светлой темы указывается путь к черному лого, для темной -- к белому.
Виджет вызывает `Image.asset(context.assets.logo)` и остается универсальным.

### ThemeManager вне дерева виджетов

Менеджер сам слушает `onPlatformBrightnessChanged`. Корневой `MaterialApp` перестраивается
только при фактической смене темы. Изменения `MediaQuery` (размер окна, клавиатура)
не вызывают полный ребилд.

### Контракты как защита от пропусков

При добавлении новой темы (например, `HighContrast`) компилятор потребует реализовать
все токены. Ситуация "забыли цвет кнопки в темной теме" исключена на уровне типизации.

## Генерация ассетов

### Инструменты

`flutter_gen_runner` -- генерирует типобезопасные ссылки на ассеты (`Assets.uiKit.images.bodyStates.emptyBody`).

### Текущее расположение

**Путь:** `lib/core/gen/assets.gen.dart`

Это вынужденная мера в условиях single-package архитектуры. `flutter_gen` генерирует
один файл на весь проект, поэтому он лежит в `core` -- единственном слое,
доступном всем остальным (`App`, `Features`).

### Как должно быть в multi-package

В полноценной модульной архитектуре каждый пакет владеет своими ассетами
и генерирует собственный `assets.gen.dart`:

```
packages/
  ui_kit/
    assets/
    lib/gen/assets.gen.dart    # ассеты UI Kit
    pubspec.yaml               # flutter_gen настроен здесь
  feature_inspections/
    assets/
    lib/gen/assets.gen.dart    # ассеты фичи
    pubspec.yaml
```

При миграции на multi-package: перенести ассеты в соответствующие пакеты,
добавить `flutter_gen` конфиг в каждый `pubspec.yaml`, удалить общий `lib/core/gen/`.

## Правила расширения

- **Без хардкода**: Hex-код или `fontSize` в файлах фич -- архитектурный долг.
  Все значения через theme extensions.
- **Контракт -> реализация -> UI**: новый токен сначала в `Base`-класс, потом в палитры,
  потом в виджет.
- **Типографика через контекст**: шрифты всегда через `context.textStyles`,
  чтобы подхватывать настройки Google Fonts и темы.
