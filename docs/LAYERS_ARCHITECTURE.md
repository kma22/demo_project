# Архитектурный подход и разделение по слоям

В данном документе описаны ключевые принципы архитектуры проекта, структура слоев и правила разработки, которыми необходимо руководствоваться при расширении функционала.

## Как устроена архитектура
Проект базируется на принципах **чистой модульности**. Основные идеи:
*   **Слабая связанность**: Фичи ничего не знают друг о друге напрямую.
*   **Работа через интерфейсы**: Компоненты общаются через абстракции. Это позволяет легко менять реализацию, не ломая всё вокруг.
*   **Оркестрация сверху**: Все зависимости и маршруты «склеиваются» на уровне приложения (`App Layer`).

## Слои приложения

### 1. Слой приложения (App Layer)
**Путь:** `lib/app/`
Точка сборки проекта. Здесь всё соединяется воедино.
*   **Что внутри**: Инициализация, глобальный DI, настройка роутера.
*   **Точки входа**: `main_dev.dart` и `main_prod.dart`.

### 2. Слой ядра (Core Layer)
**Путь:** `lib/core/`
Набор общих инструментов и сервисов. Это «фундамент», который не зависит от конкретных фич.
*   **Сеть**: Работа с API, обработка ошибок.
*   **Хранилище**: База данных (Drift), Secure Storage.
*   **Навигация**: Общие интерфейсы для переходов.
*   **Инфраструктура**: Логирование, DI-конфиги.

### 3. Слой фич (Features Layer)
**Путь:** `lib/features/`
Здесь живет бизнес-логика. Каждая фича — это отдельный мини-модуль.
*   **Структура**: Внутри фичи могут быть свои `data`, `domain` и `presentation`, если логика сложная.
*   **Автономность**: Фичи не должны импортировать друг друга. Если нужно общее — выносим в Core.

## Правила игры

### 1. Зависимости и память
*   **Синглтоны — только для базы**: Используйте `@singleton` только для глобальных вещей (база, API-клиент).
*   **Удаляйте за собой**: Логику фич (BLoC, UseCases) лучше помечать как `@injectable`, чтобы они не висели в памяти вечно.
*   **Интерфейсы — это важно**: Всегда регистрируйте реализацию через интерфейс. Это упростит тесты и будущие правки.

### 2. Ошибки
*   Никаких `DioException` в UI. Все сетевые «сюрпризы» должны превращаться в понятные доменные ошибки еще в репозитории.

### 3. Навигация
*   Фича не знает, куда она ведет дальше. Она просто вызывает метод интерфейса навигации, а «склейка» путей происходит в App слое.
